# CMDB 数据库分片与索引优化方案

## 概述

基于多专家分析结果，本方案针对NewBee CMDB的EAV动态属性模式和多租户架构，提供完整的数据库分片和索引优化解决方案。

## 1. 分片策略设计

### 1.1 基于租户的水平分片

**分片维度**: `tenant_id`
**分片算法**: 一致性哈希 + 取模备份

```sql
-- 分片路由算法
shard_id = tenant_id % shard_count
backup_shard_id = (tenant_id + 1) % shard_count
```

### 1.2 分片表命名规范

```sql
-- 主要业务表分片命名
cmdb_cis_shard_{shard_id}
cmdb_value_texts_shard_{shard_id}
cmdb_value_integers_shard_{shard_id}
cmdb_value_floats_shard_{shard_id}
cmdb_value_datetimes_shard_{shard_id}
cmdb_value_jsons_shard_{shard_id}
cmdb_ci_relations_shard_{shard_id}
cmdb_ci_permissions_shard_{shard_id}
```

### 1.3 分片配置

**初始分片数量**: 8个分片
**分片节点**: 支持动态扩容到16、32个分片
**负载均衡**: 基于数据量和QPS的智能分片

## 3. 查询优化策略

### 3.1 EAV模式查询重写

**优化前查询**：
```sql
-- 性能差：多次子查询
SELECT c.id, c.status,
    (SELECT value FROM cmdb_value_texts WHERE ci_id = c.id AND attr_id = 1) as hostname,
    (SELECT value FROM cmdb_value_integers WHERE ci_id = c.id AND attr_id = 2) as cpu_count
FROM cmdb_cis c 
WHERE c.tenant_id = 1 AND c.type_id = 100;
```

**优化后查询**：
```sql
-- 性能好：单次LEFT JOIN
SELECT c.id, c.status, vt.value as hostname, vi.value as cpu_count
FROM cmdb_cis_shard_1 c
LEFT JOIN cmdb_value_texts_shard_1 vt ON c.id = vt.ci_id 
    AND vt.attr_id = 1 AND vt.tenant_id = c.tenant_id
LEFT JOIN cmdb_value_integers_shard_1 vi ON c.id = vi.ci_id 
    AND vi.attr_id = 2 AND vi.tenant_id = c.tenant_id  
WHERE c.tenant_id = 1 AND c.type_id = 100
ORDER BY c.id
LIMIT 100;
```

### 3.2 分片查询路由优化

```go
// 查询路由器设计
type ShardQueryRouter struct {
    shardConfig  *ShardConfig
    shardNodes   map[string]*sql.DB
    queryBuilder *OptimizedQueryBuilder
}

func (r *ShardQueryRouter) ExecuteQuery(ctx context.Context, query *Query) (*Result, error) {
    if query.HasTenantFilter() {
        // 单分片查询
        shardKey := r.getShardKey(query.TenantID)
        return r.executeSingleShard(ctx, shardKey, query)
    } else {
        // 跨分片并行查询
        return r.executeParallelShards(ctx, query)
    }
}
```

## 5. 分片管理工具

### 5.1 分片路由配置

```yaml
# shard_config.yaml
shard_router:
  strategy: "consistent_hash"
  initial_shard_count: 8
  max_shard_count: 32
  rebalance_threshold: 0.8
  
shard_nodes:
  shard_0:
    host: "cmdb-db-shard-0"
    port: 3306
    database: "cmdb_shard_0"
    weight: 100
  shard_1:
    host: "cmdb-db-shard-1"
    port: 3306
    database: "cmdb_shard_1"
    weight: 100
    
tenant_overrides:
  1001: "shard_0"  # 大租户独立分片
  1002: "shard_1"  # 大租户独立分片
```

### 5.2 数据迁移脚本

```bash
#!/bin/bash
# migrate_shard.sh - 分片数据迁移脚本

TENANT_ID=$1
SOURCE_SHARD=$2
TARGET_SHARD=$3

echo "开始迁移租户 $TENANT_ID 从分片 $SOURCE_SHARD 到 $TARGET_SHARD"

# 1. 迁移CI主表数据
mysql -h $TARGET_SHARD -e "
INSERT INTO cmdb_cis SELECT * FROM $SOURCE_SHARD.cmdb_cis 
WHERE tenant_id = $TENANT_ID"

# 2. 迁移Value表数据
for table in value_texts value_integers value_floats value_datetimes value_jsons; do
  mysql -h $TARGET_SHARD -e "
  INSERT INTO cmdb_$table SELECT * FROM $SOURCE_SHARD.cmdb_$table 
  WHERE tenant_id = $TENANT_ID"
done

# 3. 迁移关系表数据
mysql -h $TARGET_SHARD -e "
INSERT INTO cmdb_ci_relations SELECT * FROM $SOURCE_SHARD.cmdb_ci_relations 
WHERE tenant_id = $TENANT_ID"

echo "数据迁移完成"
```
