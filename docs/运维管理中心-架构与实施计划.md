# 运维管理中心（Ops Center）- 架构设计与实施计划

> 版本: v0.1
> 适用范围: newbee 全仓；与 cmdb、nb-agent、worker（proxy 复用）联动
> 编码规范: 严格遵循 CLAUDE.md（多租户、数据权限、Hook、禁止原生SQL）

## 1. 背景与目标

基于现有 CMDB 的资产建模与发现能力，构建“运维管理中心（Ops Center）”微服务，形成如下通路：

运维管理中心 <-> Proxy <-> (SSH/Telnet/VNC/RDP/NB-Agent) <-> 目标设备（主机/网络/安全设备）

目标：
- 统一会话与任务编排：会话（交互式）与任务（批量/自动化）双引擎并行。
- 与 CMDB 深度融合：以 CI 为“访问画像”的真相源，驱动策略与选路。
- 兼容/渐进演进：复用 worker 作为 Proxy 的协议网关；nb-agent 作为主机侧执行器。
- 企业级安全：多租户隔离、数据权限、强认证、全程审计、合规加固。

## 2. 现状分析与差距评估

### 2.1 相关模块现状
- CMDB（cmdb/）
  - 架构文档与 API 体系完善，适合作为资产真相源（cmdb/rpc/doc/v1.0.0-architecture.md）。
- nb-agent（nb-agent/）
  - 存在“Center/Proxy/Agent”分层的设计文档与 Agent 侧的 Proxy 连接管理接口（nb-agent/docs/proxy-design.md、nb-agent/docs/agent-interface-spec.md）。
  - 代码包含 RemoteTask 模型并支持 Source=proxy/center（nb-agent/internal/biz/remote_task.go）。
  - 实际“Proxy 服务端”未见落地实现（存在设计与接口，缺运行中的 Proxy 进程）。
- worker（worker/）
  - 已实现 WebSocket 隧道与 Guacamole/guacd 代理，提供 RDP/VNC/Telnet/SSH 的 WS 接入（worker/cmd/agent/main.go 路由集）。
  - 存在 WS 安全风险未闭环（docs/SECURITY_ISSUES.md 中标注），认证/授权缺口需要补齐。
- unified-io（unified-io/）
  - 内含 Worker 注册/健康日志等通用模型，可复用为 Proxy 注册/健康的参考或共用能力。

### 2.2 差距与潜在问题
- Proxy 角色双重性：
  - 现阶段“协议网关（WS 隧道/guacd 代理）”已具备（在 worker 内）。
  - “区域代理（Agent 汇聚、任务分发、中继与上报）”能力在 nb-agent 文档中设计充分，但代码未完备，需要分阶段落地。
- 统一认证/租户透传不完善：
  - worker 的 WS 接口缺少统一 JWT 校验与租户上下文透传；可能导致跨租户会话风险。
- 审计与合规：
  - 需要标准化“会话令牌 -> 审计主体 -> 录屏/命令回放 -> 审计落库”的端到端链路。
- CMDB 访问画像：
  - CI 侧需绑定“协议能力、端口、凭证引用、Agent 存在性、首选 Proxy、跳板链路”等访问元数据，建议以“关联模型”维护，避免污染 CMDB 核心实体。
- 稳定性与容量：
  - Proxy（worker）目前更偏“协议隧道”，缺少注册、健康、容量状态等编排信号，Center 难以实现就近选路与负载控制。

### 2.3 设计修正（与实现对齐）
- Proxy 通信阶段性策略：优先采用 REST 注册/心跳，消息队列/NATS 等放入 Phase 3，避免早期复杂度（与 nb-agent 文档不冲突，属长期演进）。
- 鉴权/多租户：worker 当前未使用统一中间件（integration），需在其内部实现 WS/HTTP 统一 JWT 鉴权与租户透传，采用“可开关”灰度兼容旧路径。
- 访问画像位置：优先在 Ops Center 内落库 AccessProfile（引用 CI），避免修改 CMDB 核心模型；后续再评估迁移到 CMDB 的可行性。
- 审计：在 worker 增加轻量埋点（连接/断开/异常/命令透传），由 Ops Center 统一收敛（兼容日志异步写入与压采样）。

## 3. 目标架构与分层

### 3.1 总体架构

```
┌─────────────────────────────────────────────┐
│               运维管理中心（Ops Center）    │
│  API/UI  调度/策略  凭证/审计  选路/监控     │
└───────────────▲────────────────────────────┘
                │ JWT/mTLS + 多租户 + 审计上下文
        ┌───────┴───────────────────────────────────────┐
        │                                               │
┌───────┴───────┐                               ┌───────┴───────┐
│   Proxy-A(复用 worker) │  ...（多活） ...       │   Proxy-B(复用 worker) │
│ WS隧道/guacd  健康  容量  认证  审计  选路信号      │
└───────▲───────┘                               └───────▲───────┘
        │                                               │
        │                               Agent 长连接（后续阶段）
        │                                               │
┌───────┴───────┐                               ┌───────┴───────┐
│  nb-agent（装载端） │  命令/文件/巡检/采集/上报        │  目标设备（无Agent） │ SSH/Telnet/RDP/VNC
└────────────────┘                               └────────────────┘
```

说明：
- Phase 1：复用 worker 作为“协议网关型 Proxy”，Ops Center 直调 nb-agent 执行任务。
- Phase 2：补齐 Proxy↔Agent 的长连接与任务分发，Center 不再直连 Agent。
- 全链路强制 mTLS + JWT + 多租户/DataPerm 中间件。

### 3.2 关键边界
- CMDB：资产真相源；Ops Center 引用 CI 并按“访问画像（access profile）”生成会话/任务计划。
- Proxy：统一接入层，为会话/任务提供会话隧道与网络触达；上报健康与容量用于选路。
- nb-agent：优先选择的主机端执行器，能提供稳定与丰富的上下文（日志、文件、系统信息等）。

## 4. 数据与安全设计

### 4.1 租户与数据权限
- 新增实体均包含 `TenantMixin`；所有查询均通过 ent Hook 自动附加租户过滤，禁止原生 SQL。
- API 注册 Authority, TenantCheck, DataPerm 中间件，遵循 CLAUDE.md。

### 4.2 认证与令牌
- 会话令牌（Session Token）：短期 JWT，包含 tenantId、userId、ciId、protocol、target、expiry、sessionId、nonce、权限范围（禁止文件上传/复制等）。
- 任务令牌（Task Token）：短期 JWT，绑定任务 id 与参数摘要，防重放与越权；Proxy/Agent 均校验。
- JWKS/密钥轮转：Center 侧提供 JWKS，Proxy/Agent 拉取缓存并定期轮转；引入 Kid 控制。
 - 兼容性策略：
   - worker 鉴权开关 `auth.enabled`（默认开启于灰度环境，生产强制开启）；
   - WS 握手优先使用 `Authorization: Bearer`，兼容 `?token=`，便于前端与三方工具对接；
   - Origin/Host 白名单与 RateLimit 支持动态热更新（Redis/配置中心）。

### 4.3 传输安全
- Center↔Proxy↔Agent 全链路强制 mTLS；证书与 CRL 管理纳入 Center 证书服务；
- WS 握手前完成 JWT 校验与租户上下文绑定；连接速率限制、并发配额、心跳与超时控制。

### 4.4 审计与合规
- 统一审计模型：用户/角色/租户 + CI + 协议 + 指令/屏幕事件 + 开始/结束/异常 + 证据存储（对象存储/归档）。
- 命令审计：SSH/Telnet 记录命令与返回；RDP/VNC 录屏与关键窗口 OCR（后续）。
- 敏感操作审批与风控：黑白名单实时报错拦截、二次确认策略。

## 5. 领域模型与实体

建议将 Ops Center 独立为 Go Zero 微服务，核心实体：
- Session（会话）：
  - tenant_id, user_id, ci_id, protocol, proxy_id, endpoint, status, started_at, ended_at, audit_ref。
- Task（任务）：
  - tenant_id, creator_id, source(center/proxy)、targets（ci/host/agent）、executor(nb-agent/ssh/telnet)、status、result。
- AccessProfile（访问画像）：
  - ci_id 外键，capabilities（ssh/rdp/vnc/telnet/agent）、ports、credential_ref、prefer_proxy、jump_chain、tags。
- Proxy（代理节点）：
  - region/az、capabilities、status/heartbeats、capacity、current_load、labels、endpoints。
- CredentialRef（凭证引用）：
  - 指向密管系统的引用与作用域，不落明文。

上述实体均含创建/更新/删除审计字段，含 `TenantMixin`，并由 DataPerm 限制可见范围。

## 6. 对外接口与菜单（按微服务）

### 6.1 Ops Center（新微服务）
- API 分组与接口定义：
  - 会话（/ops/session）
    - POST /ops/session/create
      - 入参：{ ciId: string, protocol: enum[ssh|telnet|rdp|vnc], options?: {port?:number,jump?:string[],resolution?:string}, comment?:string }
      - 逻辑：读取 AccessProfile + CMDB，选路 Proxy，生成短期 JWT（Session Token）。
      - 返回：{ sessionId, wsUrl, token, proxyId, expiresAt }
    - POST /ops/session/close
      - 入参：{ sessionId }
      - 返回：{ ok: true }
    - GET /ops/session/{id}
      - 查询会话详情（租户隔离 + DataPerm）。
    - GET /ops/session?page=&size=&status=&ciId=
  - 任务（/ops/task）
    - POST /ops/task/create
      - 入参：{ name, targets:[{ciId|host,protocol}], executor?:enum[agent|ssh], command:{content,timeout,workDir,env}, credentialRefId?:string }
      - 返回：{ taskId, status:"waiting" }
    - POST /ops/task/{id}/start | /cancel
    - GET /ops/task/{id} | /list | /logs | /result
  - 代理（/ops/proxy）
    - POST /ops/proxy/register（Proxy→Center）
      - 入参：{ proxyId, region, az, endpoints:{ws,http}, capabilities:["ssh"|"rdp"|"vnc"|"telnet"], labels:object }
      - 返回：{ config:{jwksUri,mtls:{ca,certPolicy}}, heartbeatIntervalSec }
    - POST /ops/proxy/heartbeat（Proxy→Center）
      - 入参：{ proxyId, ts, load:{cpu,mem,net,session:{active,max}}, status:"up"|"degraded"|"down" }
      - 返回：{ accepted:true }
    - GET /ops/proxy/pick（Center 内部/对 UI）
      - 入参：{ protocol, region?, az?, ciId? }
      - 返回：{ proxyId, endpoint }
  - 访问画像（/ops/profile）
    - CRUD：绑定 CI 的访问参数（capabilities、ports、credentialRef、preferProxy、jumpChain、tags）
  - 凭证（/ops/credential）
    - POST /ops/credential/bind（CI 绑定 credentialRef）
    - POST /ops/credential/issue-short-token（Center→Proxy/Agent）
      - 入参：{ ciId, scope:"session"|"task", ttlSec }
      - 返回：{ token, expiresAt }
  - 审计（/ops/audit）
    - 会话/任务审计检索、下载索引（权限受控）。

- 前端菜单与权限点（建议挂载“运维中心”）：
  - 运维中心/概览（perm: ops:dashboard:view）
  - 会话管理（perm: ops:session:list/create/close/audit）
  - 任务编排（perm: ops:task:list/create/cancel/logs）
  - 代理节点（Proxy）（perm: ops:proxy:list/register/health）
  - 访问画像（perm: ops:profile:list/edit）
  - 凭证绑定（perm: ops:credential:bind/issue）
  - 审计与报表（perm: ops:audit:view/export）

### 6.2 Proxy（复用 worker + 增强）
- 必要增强接口：
  - /api/proxy/register：Proxy 启动时向 Center 注册，返回配置与密钥（mTLS/JWKS）。
  - /api/proxy/heartbeat：周期上报状态/容量/能力标签。
  - WS 隧道接口统一增加 JWT 鉴权与租户透传（现有：/api/rdp/websocket、/api/vnc/websocket、/api/telnet/websocket、/api/ssh/websocket）。
    - 握手：优先使用 `Authorization: Bearer <SessionToken>`，兼容 query `?token=`；
    - 校验：exp、tenantId、userId、ciId、protocol 一致性；
    - 限流：同用户/同租户并发阈值与速率限制。
  - /api/proxy/metrics：Prom 指标与健康检查扩展字段。
- 现有能力保持：
  - guacd 链路、通用 WS 隧道与日志。
 - 配置与兼容：
   - 新增 `security.jwt.enabled`、`security.origin_whitelist`、`security.rate_limit`；
   - 默认保持旧路由可用；开启严格模式后仅允许携带有效令牌的连接（提供例外名单以便灰度）。

### 6.3 nb-agent
- 优先复用现有 HTTP/REST 接口执行命令/文件/采集，未来引入 Proxy 长连接模式。
- 对齐 RemoteTask Source 与结果回传格式，Center 统一收敛。
 - 接口约定（示例）：
   - POST /agent/task/execute
     - 入参：{ taskId, command:{content,timeout}, targets:[{agentId|host}], env, workingDir }
     - 返回：{ taskId, status }
   - GET /agent/task/{id}/status | /result

### 6.4 CMDB
- 视情况新增“CI-AccessProfile”关联模型（遵循 CLAUDE 流程：schema→gen-ent→gen-rpc），不直接污染 CI 表结构。
- 提供查询画像的 API 给 Ops Center 使用。

## 7. 选路策略与执行器选择

选路优先级：
1) 有 agent 并在线 → nb-agent 直连优先（任务类）；
2) 否则 → Proxy 通过协议直达（会话/命令兜底）；
3) Proxy 选择：region/az 匹配 > 网络可达性（白名单/ACL）> 能力标签（rdp/vnc/ssh）> 当前负载/配额 > 故障域避让；
4) 会话策略：RDP/VNC 优先 Guacamole；SSH 支持直连与 Guacamole 两种路径（向前兼容）。

## 8. 渐进式实施路径

### Phase 1（2-3 周）——基线打通
- 建立 Ops Center 基础服务（go-zero + ent），集成 Tenant/DataPerm 中间件；
- 复用 worker 提供 WS 隧道能力，增加 JWT 认证中间件与多租户透传；
- 定义 AccessProfile 模型并与 CMDB 关联（或先落地在 Ops Center 并缓存）；
- 任务执行先直调 nb-agent（HTTP），Proxy 只承载会话；
- 审计基础链路（会话/任务最小化审计记录）。
  - worker：开启鉴权“观察模式”（仅记录、不拒绝），收集数据再转入强制模式。

### Phase 2（3-4 周）——能力整合
- Proxy 注册/心跳/健康/容量上报与就近选路；
- 凭证引用与短期凭证下发；
- 会话审计增强（RDP/VNC 录屏、SSH/Telnet 命令回放）；
- 引入部分 Agent↔Proxy 长连接（按 agent-interface-spec）。
  - 评估是否引入 MQ/NATS；如引入，仅用于任务分发与大量状态事件，不影响 WS 会话面。

### Phase 3（4+ 周）——全量代理化
- 全面启用 Proxy↔Agent 任务分发与回传，Center 不再直连 Agent；
- 跨 Proxy 容灾、会话迁移策略（断线重连/重建）、风控与合规模型完善。

## 9. 开发计划（原子任务分解）

说明：每个任务均需遵循 CLAUDE.md 开发顺序与多租户/数据权限要求；完成后最少包含：单元测试（含租户隔离）、接口联调、最小 E2E 验收。

任务台账（示例字段）：
- 任务编号、名称、模块（ops-center/proxy/agent/cmdb/ui/devops）、Owner、协作人、前置依赖、工期（理想/风险缓冲）、验收标准、测试清单、风险点/对策。

### 9.1 Ops Center 模块
1) 项目骨架与中间件集成
   - 内容：go-zero api/rpc 脚手架、ent 初始化、集成 common/middleware/integration，注册 TenantHook 与 DataPerm 拦截器。
   - 依赖：common/ 与 core 中间件可用；go.work 对齐。
   - 风险点：hook 遗漏导致租户越权；
   - 关键字段：模块=ops-center；Owner=后端；工期=2d；依赖=go.work/common；
   - 测试：
     - go test：租户隔离/数据权限隔离用例；
     - API 冒烟：鉴权链路与中间件生效；
   - 验收：最小 API 可启动并通过租户隔离测试。

2) 领域模型与表结构（Session/Task/AccessProfile/Proxy/CredentialRef）
   - 内容：按“领域模型与实体”章节建表（含 TenantMixin、审计字段）；
   - 依赖：CLAUDE.md 流程（gen-ent、gen-rpc）；
   - 风险点：模型变更影响后续 API；
   - 关键字段：模块=ops-center；Owner=后端；工期=3d；依赖=1)；
   - 测试：ent 层 CRUD + Hook 覆盖；
   - 验收：表结构生成+迁移脚本通过。

3) 会话服务 API（/ops/session）
   - 内容：创建/关闭/查询；生成短期 JWT；返回 Proxy WS 地址与参数；
   - 依赖：AccessProfile 查询、Proxy 选路；
   - 风险点：令牌拼装错误/过期策略；
   - 关键字段：模块=ops-center；Owner=后端；工期=3d；依赖=2)；
   - 测试：
     - 单测：JWT claims 正确性；
     - 集成：携带令牌访问 worker WS（本地模拟鉴权）成功；
   - 验收：端到端可建立受控会话。

4) 任务服务 API（/ops/task）
   - 内容：创建/启动/取消/查询；执行器选择（nb-agent 优先/ssh 兜底）；
   - 依赖：nb-agent 现有接口；
   - 风险点：批量目标与幂等；
   - 关键字段：模块=ops-center；Owner=后端；工期=3d；依赖=2)；
   - 测试：
     - 单测：执行器策略与幂等；
     - 联调：触发 nb-agent 任务并接收结果；
   - 验收：多目标任务稳定执行并可查询结果。

5) Proxy 管理 API（/ops/proxy）
   - 内容：注册/心跳/健康/容量上报；中心侧维护选路表；
   - 依赖：worker 侧新增注册+心跳实现；
   - 风险点：状态一致性与过期淘汰；
   - 关键字段：模块=ops-center；Owner=后端；工期=2d；依赖=2)、Proxy-1)；
   - 测试：
     - 单测：选路算法；
     - 集成：多 Proxy 抢占/就近选路；
   - 验收：在多 Proxy 环境下稳定选路。

6) 访问画像 API（/ops/profile）与 CMDB 集成
   - 内容：CI 访问画像的增删改查；与 CMDB 的 CI 关联；
   - 依赖：CMDB 查询 API；
   - 风险点：画像与 CI 版本一致性；
   - 关键字段：模块=ops-center；Owner=后端；工期=2d；依赖=2)；
   - 测试：
     - 单测：画像解析与校验；
     - 集成：CI 变更后画像同步策略；
   - 验收：画像驱动会话/任务参数正确。

7) 凭证引用/短期凭证
   - 内容：CredentialRef 管理；结合中心密管产生短期凭证下发到 Proxy/Agent；
   - 依赖：密管能力/或预置实现；
   - 风险点：明文外泄与缓存；
   - 关键字段：模块=ops-center；Owner=后端；工期=2d；依赖=2)；
   - 测试：
     - 单测：权限边界与脱敏；
     - 安测：密钥轮换与过期；
   - 验收：最小闭环（会话/任务中使用短期凭证）。

8) 审计服务（/ops/audit）
   - 内容：审计记录落库、检索与导出；
   - 依赖：Proxy/nb-agent 回传；
   - 风险点：隐私/合规；
   - 关键字段：模块=ops-center；Owner=后端；工期=3d；依赖=3)、4)、Proxy-3)；
   - 测试：
     - 单测：审计模型与查询性能；
     - 压测：大规模会话日志写入；
   - 验收：关键行为可检索与导出。

### 9.2 Proxy（worker）增强任务
1) 统一认证中间件（WS/HTTP）
   - 内容：在 `worker/cmd/agent/main.go` 注册全局 JWT 鉴权（短期会话/任务令牌），解析租户上下文；
   - 风险点：兼容原有路径（可配置开关/双栈）；
   - 关键字段：模块=proxy(worker)；Owner=后端；工期=2d；依赖=ops-center-3)；
   - 测试：
     - 单测：过期/伪造/跨租户访问拒绝；
     - 集成：与 Ops Center 会话令牌互通；
   - 验收：所有 WS 路径可控放行。

2) 注册/心跳/健康上报
   - 内容：新增 /api/proxy/register、/api/proxy/heartbeat、/api/proxy/metrics；
   - 风险点：状态抖动与时钟漂移；
   - 关键字段：模块=proxy(worker)；Owner=后端；工期=2d；依赖=ops-center-5)；
   - 测试：多实例心跳乱序处理；
   - 验收：Center 能稳定获取 Proxy 状态。

3) 审计钩子
   - 内容：在会话建立/结束/异常、命令透传关键点埋点；
   - 风险点：性能与体量；
   - 关键字段：模块=proxy(worker)；Owner=后端；工期=2d；依赖=ops-center-8)；
   - 测试：压力下丢日志率；
   - 验收：与 Center 审计表匹配。

### 9.3 nb-agent 对接任务
1) 任务执行对齐
   - 内容：Center 侧按 RemoteTask 模型创建任务，标注 Source，直调 nb-agent 执行；
   - 关键字段：模块=nb-agent；Owner=后端；工期=2d；依赖=ops-center-4)；
   - 测试：
     - 单测：结果解析/错误处理；
     - 集成：大批量任务稳定性；
   - 验收：执行路径稳定且有审计记录。

2) 代理化演进（Phase 2/3）
   - 内容：按 `agent-interface-spec` 建立 Proxy↔Agent 长连接；
   - 关键字段：模块=nb-agent+proxy；Owner=后端；工期=2-4w；依赖=Phase 1 完成；
   - 测试：
     - 断连重连；
     - 一致性与幂等；
   - 验收：Center 不再直连 Agent。

### 9.4 CMDB 画像与联动
1) 画像模型
   - 内容：在 Ops Center 持久化 AccessProfile 并绑定 CI（或在 CMDB 新建关联表，遵循 CLAUDE 流程）；

2) 发现与闭环

   - 验收：闭环打通且可灰度。

## 10. 测试策略

### 10.1 单元测试
- 租户隔离：不同 tenantId 查询互斥；
- DataPerm：Self/OwnDept/OwnDeptAndSub/CustomDept/All 覆盖；
- 令牌：过期/伪造/权限裁剪；
- 选路：多维权重与退避；

### 10.2 集成测试
- 会话：创建令牌 -> 连接 worker WS -> 断线/超时 -> 审计落库；
- 任务：Center -> nb-agent -> 结果回传 -> 审计写入；
- Proxy：注册/心跳/健康/容量 -> 选路正确性；

### 10.3 E2E/性能
- RDP/VNC 并发会话压测；SSH/Telnet 命令回放完整性；
- 心跳/指标写入在高 QPS 下的稳定性；

## 11. 风险与对策

- 会话安全：WS 鉴权缺失 → 统一 JWT + mTLS + 流量限制；
- 凭证泄露：明文/日志外泄 → 引入短期凭证，统一脱敏策略；
- 多租户越权：Hook 遗漏 → 强制 CLAUDE 流程与自动化测试守护；
- 选路不稳定：心跳抖动 → 指数平滑 + 状态过期 + 熔断与退避；
- 审计体量：录屏/日志爆炸 → 分层存储与归档策略，异步落盘。
