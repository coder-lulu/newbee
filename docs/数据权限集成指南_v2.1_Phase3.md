## 1. Phase 3架构变更概述

### 1.1 核心变更

**Phase 3（2025-10）** 数据权限架构实现了重大优化，将数据权限范围从 `sys_roles.data_scope` 字段迁移到 `sys_casbin_rules` 表统一管理。

| 项目 | Phase 2 (旧架构) | Phase 3 (新架构) | 优势 |
|------|----------------|----------------|------|
| **数据权限存储** | `sys_roles.data_scope` 字段 | `sys_casbin_rules` 表 (ptype='d') | 统一管理、灵活扩展 |
| **自定义部门ID** | `sys_roles.custom_dept_ids` 字段 | `sys_casbin_rules.v4` 字段 | 统一存储格式 |
| **权限变更通知** | 手动触发 | Redis Watcher自动通知 | 实时生效 |
| **审计日志** | 无 | 统一的Casbin规则审计 | 完整追溯 |
| **版本控制** | 无 | 支持规则版本 | 便于回滚 |

### 1.2 向后兼容性

✅ **完全向后兼容** - 现有API和Proto定义无需修改

- ✅ `RoleInfo.data_scope` 字段保留（向后兼容）
- ✅ `RoleInfo.custom_dept_ids` 字段保留
- ✅ 前端无需任何修改
- ✅ API响应格式完全兼容

**变更点**：
- ❌ `sys_roles.data_scope` 字段已移除（数据库schema变更）
- ✅ `sys_roles.custom_dept_ids` 字段保留（仅存储，查询时从casbin_rules读取）
- ✅ 运行时从 `sys_casbin_rules` 查询数据权限范围

## 2. 数据权限规则存储架构

### 2.1 数据权限规则结构 (ptype='d')

**表**: `sys_casbin_rules`

| 字段 | 说明 | 示例值 | 备注 |
|------|------|--------|------|
| `ptype` | 规则类型 | `d` | 固定为 `'d'` (data permission) |
| `v0` | 角色代码 (Subject) | `admin` | 角色的唯一标识 |
| `v1` | 租户ID (Domain) | `1` | 租户隔离 |
| `v2` | 资源类型 | `*` | 通配符表示所有资源类型 |
| `v3` | 数据权限范围 | `all` | 见下表 |
| `v4` | 自定义部门ID列表 (JSON) | `[1,2,3]` | 仅当v3=custom_dept时有效 |
| `tenant_id` | 租户ID | `1` | 用于租户隔离 |
| `service_name` | 服务名称 | `core` | 标识规则所属服务 |
| `rule_name` | 规则名称 | `管理员数据权限` | 便于管理 |
| `description` | 规则描述 | `角色admin的默认数据权限...` | 详细说明 |
| `category` | 规则分类 | `data_permission` | 固定为 `data_permission` |
| `version` | 规则版本 | `1.0.0` | 版本控制 |
| `status` | 规则状态 | `1` | 1=启用, 0=禁用 |

### 2.2 数据权限范围枚举

| 字符串值 (v3) | 枚举值 (Proto) | 说明 | 应用场景 |
|--------------|---------------|------|----------|
| `all` | `1` | 全部数据权限 | 租户管理员、系统管理员 |
| `custom_dept` | `2` | 自定义部门数据权限 | 跨部门协作、虚拟团队 |
| `own_dept_and_sub` | `3` | 本部门及下级部门数据权限 | 部门经理、团队负责人 |
| `own_dept` | `4` | 仅本部门数据权限 | 部门成员 |
| `own` | `5` | 仅本人数据权限 | 普通员工 |

## 3. 新服务数据权限接入指南

### 3.1 必要步骤

**前置条件**：
1. 服务已接入多租户架构（使用 `TenantMixin`）
2. 表结构包含必要字段：`tenant_id`, `department_id`, `user_id`
3. 已导入公共库：`github.com/coder-lulu/newbee-common`

**接入步骤**：

#### 步骤1: 导入数据权限库

```go
import (
    "github.com/coder-lulu/newbee-common/orm/ent/hooks"
)
```

#### 步骤2: 注册数据权限拦截器（RPC服务）

```go
// 在 internal/svc/service_context.go 中

func NewServiceContext(c config.Config) *ServiceContext {
    // 1. 创建ent客户端
    db := ent.NewClient(...)

    // 2. 注册租户Hook (必须，优先级最高)
    db.Use(hooks.TenantMutationHook())
    db.Intercept(hooks.TenantQueryInterceptor())

    // 3. 注册数据权限拦截器
    // 方式A: 自动注册（推荐，适用于标准表结构）
    hooks.RegisterDataPermissionInterceptorsWithTenant(db,
        "users",        // 表名列表
        "departments",
        "positions",
        "roles",
        "data_sources",
        "data_targets",
        // ... 其他需要数据权限控制的表
    )

    // 方式B: 手动注册（自定义配置）
    db.Use(hooks.NewEnhancedDataPermInterceptor(&hooks.EnhancedDataPermissionConfig{
        Enabled:           true,
        DepartmentField:   "department_id",
        UserField:         "created_by",
        SkipSystemContext: true,
        UseStateManager:   true,
    }))

    return &ServiceContext{
        Config: c,
        DB:     db,
    }
}
```

#### 步骤3: 添加API中间件（API服务）

```go
// 在 api 定义文件中（.api）

@server(
    group: user
    // 无需配置 jwt: Auth （已由统一中间件处理）
    // 数据权限会自动应用
)
service YourService {
    @handler getUsers
    post /user/list (UserListReq) returns (UserListResp)
}
```

**重要提醒**：
- ❌ 不要在 `.api` 文件中添加 `jwt: Auth` 配置（会导致重复认证）
- ✅ 统一中间件会自动处理认证、租户检查和数据权限

#### 步骤4: 确保表Schema包含必要字段

```go
// 在 ent/schema/your_entity.go 中
```

### 3.2 数据权限自动生效

**无需手动编写权限逻辑** - 数据权限拦截器会自动：

1. **租户隔离** - 自动添加 `WHERE tenant_id = ?` 条件
2. **数据权限过滤** - 根据用户角色自动过滤数据范围
3. **SystemContext支持** - 系统级操作自动跳过权限检查

```go
// 示例: 查询用户列表（自动应用数据权限）

func (l *GetUserListLogic) GetUserList(in *core.UserListReq) (*core.UserListResp, error) {
    // ✅ 无需手动添加任何过滤条件
    // 拦截器会自动根据用户的数据权限范围过滤

    query := l.svcCtx.DB.User.Query()

    // 添加业务过滤条件
    if in.Username != nil && *in.Username != "" {
        query.Where(user.UsernameContains(*in.Username))
    }

    if in.Status != nil {
        query.Where(user.StatusEQ(*in.Status))
    }

    // 执行查询
    // 数据权限会自动应用：
    // - 管理员: 看到所有用户
    // - 部门经理: 看到本部门及下属部门的用户
    // - 普通员工: 仅看到自己的记录
    results, err := query.
        Order(ent.Desc(user.FieldCreatedAt)).
        Offset(int((in.Page - 1) * in.PageSize)).
        Limit(int(in.PageSize)).
        All(l.ctx)

    if err != nil {
        return nil, dberrorhandler.DefaultEntError(l.Logger, err, in)
    }

    return convertToResponse(results), nil
}
```

### 3.3 系统级操作使用SystemContext

**场景**: 需要绕过租户隔离和数据权限（如租户初始化、数据同步）

```go
import "github.com/coder-lulu/newbee-common/orm/ent/hooks"

func (l *InitTenantLogic) InitTenant(in *core.TenantInfo) (*core.BaseIDResp, error) {
    // 创建SystemContext绕过租户隔离
    systemCtx := hooks.NewSystemContext(l.ctx)

    // 在事务中创建租户基础数据
    err := l.svcCtx.DB.WithTx(systemCtx, func(tx *ent.Tx) error {
        // 1. 创建租户管理员角色
        adminRole, err := tx.Role.Create().
            SetName("租户管理员").
            SetCode("tenant_admin").
            SetTenantID(in.TenantID).
            SetDepartmentID(1).
            SetStatus(1).
            Save(systemCtx)
        if err != nil {
            return err
        }

        // 2. 为管理员角色创建数据权限规则
        _, err = tx.CasbinRule.Create().
            SetPtype("d").
            SetV0(adminRole.Code).
            SetV1(fmt.Sprintf("%d", in.TenantID)).
            SetV2("*").
            SetV3("all").  // 全部数据权限
            SetV4("").
            SetServiceName("core").
            SetRuleName(fmt.Sprintf("%s数据权限", adminRole.Name)).
            SetDescription(fmt.Sprintf("角色%s的默认数据权限规则，数据范围：all（全部数据）", adminRole.Name)).
            SetCategory("data_permission").
            SetVersion("1.0.0").
            SetStatus(1).
            SetTenantID(in.TenantID).
            Save(systemCtx)

        if err != nil {
            return err
        }

        return nil
    })

    if err != nil {
        return nil, err
    }

    // 发布Redis通知，触发Casbin策略重新加载
    updateMsg := fmt.Sprintf("UpdatePolicy:tenant_%d:data_perm", in.TenantID)
    l.svcCtx.Redis.Publish(l.ctx, "casbin_watcher", updateMsg)

    return &core.BaseIDResp{Id: in.TenantID}, nil
}
```

## 4. 数据权限查询与更新

### 4.1 数据权限查询Helper函数

**位置**: `core/rpc/internal/logic/role/data_scope_helper.go`

```go
package role

import (
    "context"
    "encoding/json"
    "fmt"

    "github.com/coder-lulu/newbee-common/orm/ent/hooks"
    "github.com/coder-lulu/newbee-core/rpc/ent"
    "github.com/coder-lulu/newbee-core/rpc/ent/casbinrule"
)

// getDataScopeFromCasbin 从sys_casbin_rules查询角色的数据权限范围
func getDataScopeFromCasbin(ctx context.Context, db *ent.Client, roleCode string, tenantID uint64) (uint32, error) {
    // 使用SystemContext绕过租户隔离
    systemCtx := hooks.NewSystemContext(ctx)

    // 查询数据权限规则（ptype='d'）
    rule, err := db.CasbinRule.Query().
        Where(
            casbinrule.PtypeEQ("d"),                      // 数据权限规则
            casbinrule.V0EQ(roleCode),                    // 角色代码
            casbinrule.V1EQ(fmt.Sprintf("%d", tenantID)), // 租户ID
        ).
        First(systemCtx)

    if err != nil {
        if ent.IsNotFound(err) {
            return 5, nil // 默认为 own (最严格的权限)
        }
        return 0, err
    }

    // 将v3字段（数据权限范围字符串）转换为枚举值
    return dataScopeStringToEnum(rule.V3), nil
}

// getCustomDeptIdsFromCasbin 从sys_casbin_rules查询角色的自定义部门ID列表
func getCustomDeptIdsFromCasbin(ctx context.Context, db *ent.Client, roleCode string, tenantID uint64) ([]uint64, error) {
    systemCtx := hooks.NewSystemContext(ctx)

    rule, err := db.CasbinRule.Query().
        Where(
            casbinrule.PtypeEQ("d"),
            casbinrule.V0EQ(roleCode),
            casbinrule.V1EQ(fmt.Sprintf("%d", tenantID)),
        ).
        First(systemCtx)

    if err != nil {
        if ent.IsNotFound(err) {
            return []uint64{}, nil
        }
        return nil, err
    }

    // 解析v4字段（JSON格式的部门ID列表）
    if rule.V4 == "" {
        return []uint64{}, nil
    }

    var deptIds []uint64
    if err := json.Unmarshal([]byte(rule.V4), &deptIds); err != nil {
        return nil, fmt.Errorf("failed to parse custom dept ids: %w", err)
    }

    return deptIds, nil
}

// dataScopeStringToEnum 将数据权限范围字符串转换为枚举值
func dataScopeStringToEnum(dataScope string) uint32 {
    switch dataScope {
    case "all":
        return 1
    case "custom_dept":
        return 2
    case "own_dept_and_sub":
        return 3
    case "own_dept":
        return 4
    case "own":
        return 5
    default:
        return 5 // 默认为 own (最严格的权限)
    }
}

// dataScopeEnumToString 将数据权限范围枚举值转换为字符串（用于更新操作）
func dataScopeEnumToString(dataScope uint32) string {
    switch dataScope {
    case 1:
        return "all"
    case 2:
        return "custom_dept"
    case 3:
        return "own_dept_and_sub"
    case 4:
        return "own_dept"
    case 5:
        return "own"
    default:
        return "own" // 默认值
    }
}
```

```go
type GetRoleByIdLogic struct {
    ctx    context.Context
    svcCtx *svc.ServiceContext

func NewGetRoleByIdLogic(ctx context.Context, svcCtx *svc.ServiceContext) *GetRoleByIdLogic {

        ctx:    ctx,
        svcCtx: svcCtx,
        Logger: logx.WithContext(ctx),
    }

func (l *GetRoleByIdLogic) GetRoleById(in *core.IDReq) (*core.RoleInfo, error) {
    // 1. 查询角色基础信息
    result, err := l.svcCtx.DB.Role.Get(l.ctx, in.Id)
    if err != nil {
        return nil, dberrorhandler.DefaultEntError(l.Logger, err, in)
    }

    // 2. 构建响应
    roleInfo := &core.RoleInfo{
        Id:            &result.ID,
        Name:          &result.Name,
        Code:          &result.Code,
        DefaultRouter: &result.DefaultRouter,
        Status:        &result.Status,
        Remark:        &result.Remark,
        OrderNo:       &result.OrderNo,
        CreatedAt:     pointy.GetPointer(result.CreatedAt.UnixMilli()),
        UpdatedAt:     pointy.GetPointer(result.UpdatedAt.UnixMilli()),
    }

    // 3. 🔥 Phase 3: 从sys_casbin_rules查询数据权限范围
    dataScope, err := getDataScopeFromCasbin(l.ctx, l.svcCtx.DB, result.Code, result.TenantID)
    if err != nil {
        logx.Errorw("Failed to query data scope from casbin",
            logx.Field("role_code", result.Code),
            logx.Field("tenant_id", result.TenantID),
            logx.Field("error", err))
        // 查询失败时设置默认值
        dataScope = 5 // own (最严格的权限)
    }
    roleInfo.DataScope = pointy.GetPointer(dataScope)

    // 4. 🔥 Phase 3: 从sys_casbin_rules查询自定义部门ID列表
    customDeptIds, err := getCustomDeptIdsFromCasbin(l.ctx, l.svcCtx.DB, result.Code, result.TenantID)
    if err != nil {
        logx.Errorw("Failed to query custom dept ids from casbin",
            logx.Field("role_code", result.Code),
            logx.Field("tenant_id", result.TenantID),
            logx.Field("error", err))
        customDeptIds = []uint64{}
    }
    roleInfo.CustomDeptIds = customDeptIds

    return roleInfo, nil
}
```

### 4.3 角色数据权限更新示例

**文件**: `core/rpc/internal/logic/role/assign_role_data_scope_logic.go`

```go
package role

import (
    "context"
    "encoding/json"
    "fmt"

    "github.com/zeromicro/go-zero/core/logx"
    "github.com/coder-lulu/newbee-common/orm/ent/hooks"
    "github.com/coder-lulu/newbee-core/rpc/ent"
    "github.com/coder-lulu/newbee-core/rpc/ent/casbinrule"
    "github.com/coder-lulu/newbee-core/rpc/internal/svc"
    "github.com/coder-lulu/newbee-core/rpc/types/core"
)

type AssignRoleDataScopeLogic struct {
    ctx    context.Context
    svcCtx *svc.ServiceContext
    logx.Logger
}

func NewAssignRoleDataScopeLogic(ctx context.Context, svcCtx *svc.ServiceContext) *AssignRoleDataScopeLogic {
    return &AssignRoleDataScopeLogic{
        ctx:    ctx,
        svcCtx: svcCtx,
        Logger: logx.WithContext(ctx),
    }
}

func (l *AssignRoleDataScopeLogic) AssignRoleDataScope(in *core.AssignRoleDataScopeReq) (*core.BaseResp, error) {
    // 1. 查询角色信息
    role, err := l.svcCtx.DB.Role.Get(l.ctx, in.Id)
    if err != nil {
        return nil, err
    }

    // 2. 在事务中更新数据权限
    err = l.svcCtx.DB.WithTx(l.ctx, func(tx *ent.Tx) error {
        // 2.1 更新角色表中的custom_dept_ids字段（保留字段，用于向后兼容）
        err := tx.Role.UpdateOneID(in.Id).
            SetNotNilCustomDeptIds(in.CustomDeptIds).
            Exec(l.ctx)
        if err != nil {
            return err
        }

        // 2.2 🔥 Phase 3: 更新sys_casbin_rules表中的数据权限规则
        return l.updateCasbinDataPermRules(tx, role, in)
    })

    if err != nil {
        return nil, err
    }

    // 3. 发布Redis通知，触发Casbin策略重新加载
    updateMsg := fmt.Sprintf("UpdatePolicy:tenant_%d:data_perm", role.TenantID)
    l.svcCtx.Redis.Publish(l.ctx, "casbin_watcher", updateMsg)

    return &core.BaseResp{Msg: "common.updateSuccess"}, nil
}

// updateCasbinDataPermRules 更新Casbin数据权限规则
func (l *AssignRoleDataScopeLogic) updateCasbinDataPermRules(
    tx *ent.Tx,
    role *ent.Role,
    in *core.AssignRoleDataScopeReq,
) error {
    systemCtx := hooks.NewSystemContext(l.ctx)

    // 1. 删除旧的数据权限规则
    _, err := tx.CasbinRule.Delete().
        Where(
            casbinrule.PtypeEQ("d"),
            casbinrule.V0EQ(role.Code),
            casbinrule.TenantIDEQ(role.TenantID),
        ).
        Exec(systemCtx)
    if err != nil {
        return fmt.Errorf("failed to delete old data permission rule: %w", err)
    }

    // 2. 创建新的数据权限规则
    dataScopeStr := dataScopeEnumToString(*in.DataScope)
    customDeptIdsJSON := ""
    if len(in.CustomDeptIds) > 0 {
        bytes, err := json.Marshal(in.CustomDeptIds)
        if err != nil {
            return fmt.Errorf("failed to marshal custom dept ids: %w", err)
        }
        customDeptIdsJSON = string(bytes)
    }

    _, err = tx.CasbinRule.Create().
        SetPtype("d").
        SetV0(role.Code).
        SetV1(fmt.Sprintf("%d", role.TenantID)).
        SetV2("*").
        SetV3(dataScopeStr).
        SetV4(customDeptIdsJSON).
        SetServiceName("core").
        SetRuleName(fmt.Sprintf("%s数据权限", role.Name)).
        SetDescription(fmt.Sprintf("角色%s的数据权限规则，数据范围：%s", role.Name, dataScopeStr)).
        SetCategory("data_permission").
        SetVersion("1.0.0").
        SetStatus(1).
        SetTenantID(role.TenantID).
        Save(systemCtx)
    if err != nil {
        return fmt.Errorf("failed to create data permission rule: %w", err)
    }

    return nil
}
```

```go
// InitTenant 初始化租户
func (l *InitTenantLogic) InitTenant(in *core.TenantInfo) (*core.BaseIDResp, error) {
    systemCtx := hooks.NewSystemContext(l.ctx)

    err := l.svcCtx.DB.WithTx(systemCtx, func(tx *ent.Tx) error {
        // 1. 创建租户
        tenant, err := tx.Tenant.Create().
            SetName(*in.Name).
            SetCode(*in.Code).
            SetStatus(1).
            Save(systemCtx)
        if err != nil {
            return err
        }

        // 2. 创建租户管理员角色
        adminRole, err := tx.Role.Create().
            SetName("租户管理员").
            SetCode("tenant_admin").
            SetTenantID(tenant.ID).
            SetDepartmentID(1).
            SetStatus(1).
            Save(systemCtx)
        if err != nil {
            return err
        }

        // 3. 🔥 Phase 3: 初始化管理员数据权限规则
        if err := l.initAdminDataPermissions(systemCtx, tx, adminRole, tenant.ID); err != nil {
            return err
        }

        // 4. 创建普通用户角色
        userRole, err := tx.Role.Create().
            SetName("普通用户").
            SetCode("user").
            SetTenantID(tenant.ID).
            SetDepartmentID(1).
            SetStatus(1).
            Save(systemCtx)
        if err != nil {
            return err
        }

        // 5. 🔥 Phase 3: 初始化普通用户数据权限规则
        if err := l.initUserDataPermissions(systemCtx, tx, userRole, tenant.ID); err != nil {
            return err
        }

        return nil
    })

    if err != nil {
        return nil, err
    }

    return &core.BaseIDResp{Id: in.Id}, nil
}
```

## 6. 迁移指南

### 6.1 从Phase 2迁移到Phase 3

**迁移影响**：
- ✅ API接口：无影响（完全向后兼容）
- ✅ Proto定义：无影响
- ✅ 前端代码：无影响
- ⚠️ 数据库：需要执行迁移脚本

**迁移步骤**：

#### 步骤1: 数据迁移

**迁移脚本**: `/opt/code/newbee/core/rpc/migrations/phase3_remove_data_scope_field.sql`

```sql
-- ============================================================================
-- Phase 3 数据权限架构迁移脚本
-- 功能: 将 sys_roles.data_scope 字段迁移到 sys_casbin_rules 表
-- 版本: v2.1
-- 日期: 2025-10-22
-- ============================================================================

BEGIN;

-- 1. 为每个角色创建数据权限规则（迁移现有数据）
INSERT INTO sys_casbin_rules (
    ptype, v0, v1, v2, v3, v4,
    tenant_id, service_name, rule_name, description, category, version, status,
    created_at, updated_at
)
SELECT
    'd' AS ptype,                                       -- 数据权限规则类型
    r.code AS v0,                                       -- 角色代码
    CAST(r.tenant_id AS VARCHAR) AS v1,                 -- 租户ID
    '*' AS v2,                                          -- 资源类型（所有）
    CASE r.data_scope                                    -- 数据权限范围（枚举转字符串）
        WHEN 1 THEN 'all'
        WHEN 2 THEN 'custom_dept'
        WHEN 3 THEN 'own_dept_and_sub'
        WHEN 4 THEN 'own_dept'
        WHEN 5 THEN 'own'
        ELSE 'own'
    END AS v3,
    CASE
        WHEN r.data_scope = 2 AND r.custom_dept_ids IS NOT NULL THEN
            -- 将自定义部门ID数组转换为JSON字符串
            '[' || array_to_string(r.custom_dept_ids, ',') || ']'
        ELSE ''
    END AS v4,
    r.tenant_id,                                        -- 租户ID
    'core' AS service_name,                             -- 服务名称
    r.name || '数据权限' AS rule_name,                  -- 规则名称
    '角色' || r.name || '的数据权限规则（从Phase 2迁移）' AS description,
    'data_permission' AS category,                      -- 规则分类
    '1.0.0' AS version,                                 -- 版本
    r.status,                                           -- 状态
    NOW() AS created_at,
    NOW() AS updated_at
FROM sys_roles r
WHERE NOT EXISTS (
    -- 避免重复迁移
    SELECT 1 FROM sys_casbin_rules cr
    WHERE cr.ptype = 'd'
    AND cr.v0 = r.code
    AND cr.v1 = CAST(r.tenant_id AS VARCHAR)
);

-- 2. 移除 sys_roles.data_scope 字段（已迁移到sys_casbin_rules）
ALTER TABLE sys_roles DROP COLUMN IF EXISTS data_scope;

-- 3. 验证迁移结果
DO $$
DECLARE
    role_count INTEGER;
    rule_count INTEGER;
BEGIN
    SELECT COUNT(*) INTO role_count FROM sys_roles;
    SELECT COUNT(*) INTO rule_count FROM sys_casbin_rules WHERE ptype = 'd';

    RAISE NOTICE '=== Phase 3 迁移完成 ===';
    RAISE NOTICE '角色总数: %', role_count;
    RAISE NOTICE '数据权限规则总数: %', rule_count;

    IF rule_count < role_count THEN
        RAISE WARNING '数据权限规则数量少于角色数量，请检查迁移脚本';
    END IF;
END $$;

COMMIT;
```

## 7. 故障排查

### 7.1 数据权限不生效

**症状**：用户看到了不应该看到的数据

**排查步骤**：

```sql
-- 1. 检查用户角色绑定
SELECT u.username, r.code AS role_code, ur.user_id, ur.role_id
FROM sys_users u
JOIN sys_user_roles ur ON u.id = ur.user_id
JOIN sys_roles r ON ur.role_id = r.id
WHERE u.id = <用户ID>;

-- 2. 检查角色的数据权限规则
SELECT *
FROM sys_casbin_rules
WHERE ptype = 'd'
AND v0 = '<角色代码>'
AND v1 = '<租户ID>';

-- 3. 检查数据权限拦截器是否注册
-- 在RPC日志中搜索 "RegisterDataPermissionInterceptorsWithTenant"
grep "RegisterDataPermissionInterceptorsWithTenant" /var/log/newbee-core.log
```

**常见原因**：
1. ❌ 数据权限拦截器未注册
2. ❌ sys_casbin_rules 中无数据权限规则（ptype='d'）
3. ❌ SystemContext误用（绕过了数据权限）
4. ❌ 表结构缺少必要字段（department_id/user_id）

### 7.2 数据权限规则未生效

**症状**：更新角色数据权限后，权限未生效

**排查步骤**：

```sql
-- 1. 检查sys_casbin_rules中的规则是否已更新
SELECT *
FROM sys_casbin_rules
WHERE ptype = 'd'
AND v0 = '<角色代码>'
AND tenant_id = <租户ID>
ORDER BY updated_at DESC
LIMIT 1;

-- 2. 检查Redis通知是否发布
-- 在Redis中订阅casbin_watcher频道
redis-cli SUBSCRIBE casbin_watcher
```

**解决方法**：

```bash
# 1. 手动重新加载Casbin策略
redis-cli PUBLISH casbin_watcher "UpdatePolicy:tenant_<租户ID>:data_perm"

# 2. 重启服务
systemctl restart newbee-core
```

### 7.3 自定义部门ID列表解析失败

**症状**：日志中出现 "failed to parse custom dept ids"

**排查步骤**：

```sql
-- 检查v4字段的JSON格式是否正确
SELECT v0 AS role_code, v4 AS custom_dept_ids,
       json_valid(v4::json) AS is_valid_json
FROM sys_casbin_rules
WHERE ptype = 'd'
AND v3 = 'custom_dept';
```

**正确格式**：
```json
[1,2,3,5,8]
```

**错误格式**：
```json
"1,2,3,5,8"    # ❌ 字符串格式
{1,2,3}        # ❌ 数组格式错误
[1, 2, 3]      # ✅ 正确（带空格也可以）
```

### 7.4 性能问题

**症状**：数据权限查询慢

**排查步骤**：

```sql
-- 1. 检查索引是否存在
SELECT indexname, indexdef
```
